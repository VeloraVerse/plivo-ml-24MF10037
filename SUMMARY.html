2,000 Step LLM Speedrun Summary

An analysis of custom model architecture and optimization decisions under hard constraints

Model Architecture Upgrades

We completely replaced the baseline GPT model with a modernized, state-of-the-art transformer architecture optimized for CPU efficiency and size constraints:

  • Tied Embedding-LM Head weights: Tying weight matrices saved 196,608 parameters, enabling us to increase depth (4 layers instead of 2).
  • RMSNorm (instead of LayerNorm): Removed the bias parameter and scaling computation overhead, accelerating training steps on CPU.
  • Rotary Positional Embeddings (RoPE): Replaced learned absolute positional embeddings, eliminating 49,152 parameters and improving seq length generalization.
  • SwiGLU MLP (instead of GELU): Uses three projection gates (W_g, W_u, W_d) to double capacities for identical parameter budgets.

Total Parameters: 1,967,808 (98.4% of the 2,000,000 cap)

Byte-Level BPE Tokenizer

The baseline ByteTokenizer treated Hindi characters as 3 bytes (3 tokens). To solve this sequence lengthening and token budget waste:

  • We trained a custom Byte-Level BPE Tokenizer on a 1.5MB subsample of `train_corpus.txt`.
  • The vocabulary size is 1,024 (256 basic byte tokens + 768 merges).
  • It includes a byte fallback mechanism, guaranteeing it is 100% lossless for arbitrary UTF-8 text.
  • Fast Word-Caching: Speeds up encoding to ~0.1s for dev set by tokenizing unique words and caching.

Compression Ratio: 1.91x (cuts token sequence length in half!)

Why This Configuration Wins

This setup achieves maximum quality under severe constraints because:

  • Sequence Compression: The 1.91x compression means the model sees ~2x more context per sequence, and the CPU trains on 2x fewer tokens, saving compute.
  • Architecture Efficiency: Tying weights and using RoPE/RMSNorm allows us to use 4 layers and 192 dimensions rather than a small, shallow model.
  • Hyperparameter Tuning: We verified that a peak learning rate of 2e-3 achieves significantly better convergence than 1.5e-3 or 3e-3.
  • Optimized Optimizer: AdamW with weight decay (0.1) and a cosine decay schedule prevents overfitting while ensuring smooth convergence.
